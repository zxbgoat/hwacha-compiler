hwacha-cc 工作原理

把一个 SPMD kernel 拆成两段代码：工作项之间不一致的部分变成 Hwacha 的向量取指块，在 工作线程 上以谓词执行；工作项之间一致的部分留在标量 控制线程 上，负责配置、循环和发射。其余一切都是为这个划分服务的。

一、从源码到汇编的路径

编译器真正的输入是 LLVM IR，只要 IR 里的 kernel 满足一套约定：函数带 !kernel_arg_addr_space 元数据；工作项编号通过 get_global_id(0)、get_local_id(0)、get_group_id(0)、get_local_size(0) 这几个调用取得；同步是 barrier；跨 lane 归约是 work_group_reduce_*。两个前端都把输入整理成这个形式。

OpenCL 前端

clang 以 -x cl -cl-std=CL1.2 编译，目标设为 riscv64，关掉向量化和展开，得到 -O2 形态的 IR。在这个目标上 __local 数组就是普通的内部全局变量，编译器不需要特殊的地址空间处理。

MLIR 前端

hwacha-mlir 链接 libMLIR，接收 gpu dialect 或 linalg 级别的输入。linalg 先变成并行循环；嵌套的并行循环改成顺序循环；最外层压成一维并映射为"每个 block 一个工作项"；用到的常量 sink 进 launch，次数不超过 8 的小循环展开，然后外提成 gpu.func。kernel 侧走 convert-gpu-to-nvvm 翻成 LLVM IR；宿主侧把 gpu.launch_func 降低成对 <kernel>_ct 的调用，并把 block 大小和 block 数写进 hwacha_group_size、hwacha_grid_size。内嵌的 transform 脚本（tiling、interchange）在这一切之前执行。

hwacha-cc 看到 ptx_kernel 调用约定就知道 IR 来自这条路：NVVM 特殊寄存器变成 id 调用，ctaid*ntid+tid 折叠成 get_global_id（否则地址会被归成 gather），block 大小为 1 的 kernel 把 block 编号当工作项编号，nvvm.barrier、addrspace(3) 全局变量、__nv_* 数学函数各归各位，最后再跑一遍与 clang 等价的 -O2。

汇合之后的预处理

expf（以及 llvm.exp.f32、OpenCL 的 exp）展开成直线向量算术：范围规约、六次多项式、把整数指数加进浮点的指数域。可选的 --fp-contract 把单用途的 fmul 加 fadd 融合成 fmuladd。然后 InstCombine、EarlyCSE、SimplifyCFG、LoopSimplify、LCSSA 把 IR 整理成分析期望的规范形态。

二、分析：谁是一致的，地址长什么样

KernelAnalysis 回答两个问题，代码生成的每个决定都建立在这两个答案上。

一致性

直接用 LLVM 的 UniformityInfo，配一个只回答"分歧从哪来"的最小 TTI：id 调用永不一致，归约调用的结果永远一致，其余靠数据流和控制依赖推导。分析之前先做 widenIdArithmetic，把 32 位的 id 算术链重建成 64 位，否则 sext 和 trunc 会遮住地址模式。分析结果决定每条指令去哪里执行：一致的值可以在控制线程算好，通过 vmcs 送进标量向量寄存器 vs；不一致的值只能在 vf 块里用向量寄存器 vv 算。

地址分类

每个 load 和 store 的地址用 ScalarEvolution 表示成关于全局 id 的表达式，分成四类。分类同时记录流的基址是否随某个循环推进，这是控制线程区域能把流"逐次迭代重新指向"的依据。

三、代码生成：两个线程怎么配合

控制线程 <kernel>_ct(n, args…)

每个 kernel 生成一个 C 可调用的函数：vsetcfg 配置寄存器数量，按 stripmine 循环用 vsetvl 把 n 个工作项切成一段段，每段用 vmcs 传标量输入、vmca 传流的基址、vf 启动工作线程块，最后 fence 再返回。这部分以 LLVM IR 生成，交给 llc。

工作线程 <kernel>_wt 与 _wt_r*_b*

vf 块内没有分支可用，kernel 的控制流被展平成谓词执行；向量寄存器在 vf 块之间保持不变，所以一个 kernel 可以拆成多个 vf 块由控制线程按顺序发射。这部分直接输出汇编文本。

分歧控制流

每个基本块有一个活跃掩码 vp；条件分支产生子掩码，汇合点用 vpop 做谓词逻辑合并，phi 变成沿边执行的带谓词移动。分歧循环靠"活跃集合"迭代直到没有 lane 活跃，退出 lane 的值在出口边捕获。唯一的整块跳转是共识跳转 vcjal，代价约 50 周期，所以只用于至少两条指令的块的跳过，且不在循环头使用。硬件的谓词逻辑指令不受掩码影响，因此条件谓词移动做成三输入 mux。下面是 MLIR 写的 saxpy 生成的 vf 块，边界判断变成了掩码 vp2：

saxpy_wt:
    vpset vp0
    veidx vv0
    vadd vv0, vv0, vs63          # 全局 id = 元素号 + 本段起点
    vcmpltu vp1, vv0, vs62       # gid < n
    vpop vp2, vp0, vp1, vp1, 0x80
    vpop vp3, vp0, vp1, vp1, 0x02
    @!vp2 vcjal 0, vs1, .Lsaxpy_skip0   # 没有 lane 进入时整块跳过
    @vp2 vlw vv1, va0            # x[gid]，单位步长流
    @vp2 vlw vv2, va1            # y[gid]
    @vp2 vfmul.s vv3, vs57, vv1
    @vp2 vfadd.s vv3, vv3, vv2
    @vp2 vsw vv3, va1
.Lsaxpy_skip0:
    vstop

控制线程区域

这是性能的来源。控制流一致的循环嵌套整体搬到控制线程上跑：循环的比较和跳转是标量指令，循环体的每个 kernel 基本块变成一个独立的 vf 块，每次迭代由控制线程发射。因为向量寄存器在 vf 块之间保持不变，循环携带的值可以常驻 vv 寄存器：phi coalescing 把 latch 上的新值直接算进 phi 的寄存器，内层循环出口的 LCSSA phi 也别名到同一个寄存器。每次迭代要变的标量经 vmcs 传入，随循环推进的流每次迭代重新 vmca。循环里的一致加载能不能在控制线程上做，由 BasicAA 加 TBAA 判断，有潜在别名时插 fence。

工作组、本地内存与归约

hwacha_group_size 非零时向量长度被限制为工作组大小，于是一个工作组恰好是一段 stripmine。__local 数组变成控制线程模块里的一个静态缓冲（工作组依次执行，一份就够），barrier 退化成一条 vfence。硬件唯一的跨 lane 原语是 vfirst，所以 work_group_reduce_* 走内存：各 lane 把值写进 scratch 缓冲，然后一个对数深度的树在向量寄存器里做，每层是一次跨半区的加载加运算，最后 vfence 后由 vlsw 读回一致的结果。

寄存器与输出

vv、vs、vp 以及配置成 32 位的 vw 寄存器各自线性分配，按最后使用点释放；标量输入寄存器先于临时寄存器分配以免冲突，链接寄存器在 kernel 开头就保留。控制线程的 LLVM IR 交给 llc 编译成 riscv64 汇编，与工作线程的汇编文本拼成一个 .s；MLIR 路径的宿主 IR 在 llc 之前链接进同一个模块，所以 hwacha_group_size、hwacha_grid_size 这类全局在同一个目标文件里定义。旧版 binutils 不认识的 .attribute 指示和 fmv.x.w 拼写在输出时被过滤或改写。
